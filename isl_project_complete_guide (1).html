Complete guide for the Indian Sign Language to Text Converter project — dataset, tech stack, workflow, folder structure, dependencies, and 4-week plan

What you're building
Indian Sign Language (ISL) → Text + Speech Converter
A real-time web app where a hearing-impaired person signs into their webcam and the system instantly recognizes the gesture, converts it to text, builds words letter-by-letter, and speaks them aloud. Built specifically for ISL — not ASL — which makes it rare and impactful.
What makes it stand out
ISL-specific
Most projects use ASL. ISL has far less open-source tooling, making yours genuinely useful for India's 63M+ hearing-impaired population.
Landmark-based (not pixel)
Uses 21 hand coordinate points instead of raw images — works across lighting, skin tone, and backgrounds. Smart architectural choice.
Text-to-speech output
Words are spoken aloud via pyttsx3 when confidence exceeds 80% — adds real accessibility value beyond just showing text on screen.
Deployed live
Deployed on Hugging Face Spaces — gives you a public URL to paste into your resume and demo live in interviews.

Unique talking point
Core tech terms you must know cold
MediaPipe
Google's open-source framework for real-time processing of video/audio. In your project, it detects your hand in every webcam frame and returns 21 landmark points (x, y, z coordinates). You never deal with raw pixels — MediaPipe handles all that.
Hand landmarks
The 21 key points MediaPipe detects on every hand — fingertips, knuckles, wrist, etc. Each point has x, y, z values normalized 0–1. So one hand = 63 numbers total. These numbers become your model's input features.
CNN (Convolutional Neural Network)
A type of neural network designed for image data. It learns spatial patterns — edges, shapes, textures. If you're training on images (not landmarks), you use a CNN. Think of it as a network with "visual filters" that scan across images.
LSTM (Long Short-Term Memory)
A neural network type that remembers sequences over time. Used for dynamic gestures (signs that involve movement). You don't need this for static letter recognition — but knowing the term impresses in interviews.
Feature extraction
Turning raw input into useful numbers. In your project, the 63 landmark coordinates ARE your features. In image-based approaches, a CNN extracts features automatically from pixels.
Classification
Your model's job — take 63 input numbers and output one of 26 classes (A–Z). The model assigns a probability to each class and picks the highest. That's your predicted letter.
Confidence score
The probability value of the winning class. If the model says "A with 94% confidence" — that 94% is your confidence score. You only speak the letter aloud when this exceeds a threshold (e.g. 80%).
Normalization
Scaling input values to a consistent range (0–1 or -1 to 1). MediaPipe already returns normalized coordinates, but if you collect raw pixel data, you'd divide by image width/height. Prevents large numbers from dominating the model.
OpenCV
Open Computer Vision library. Handles: opening your webcam, reading frame-by-frame, drawing boxes/text on the video feed, converting color spaces (BGR to RGB). It's the "camera manager" in your pipeline.
pyttsx3
Text-to-speech Python library that works offline. You pass it a string and it speaks it aloud through your speakers. No API key needed — runs fully locally.
Streamlit
Python library that turns a Python script into a shareable web app with zero HTML/CSS. You write Python, it renders sliders, buttons, webcam feeds, text boxes. Perfect for demos and Hugging Face deployment.
Inference
Running your trained model on new data to get a prediction. Training = learning from data. Inference = using what you learned. In your app, every webcam frame triggers inference in real time.
Overfitting
When your model memorizes training data but fails on new data. Signs: 99% training accuracy, 60% test accuracy. Fix: add Dropout layers, collect more diverse training data, use data augmentation.

Phase 1 — data collection (if building your own dataset)
Open webcam with OpenCV → pass each frame to MediaPipe → extract 21 (x,y,z) points → flatten to a 63-number array → label it with the current sign (e.g. "A") → save to a CSV row. Do 100 samples per letter. Takes about 30–40 minutes total.
Phase 2 — model training (offline, in a notebook)
Load your CSV → split into train/test (80/20) → normalize features → build a Keras neural network (Input: 63 → Dense 128 → Dropout 0.3 → Dense 64 → Dropout 0.3 → Output: 26 softmax) → train for 50 epochs → save the model as isl_model.h5 → evaluate: print accuracy, plot confusion matrix.
model = Sequential([ Dense(128, activation='relu', input_shape=(63,)), Dropout(0.3), Dense(64, activation='relu'), Dropout(0.3), Dense(26, activation='softmax') ])
Phase 3 — real-time inference loop
Load the saved model → open webcam with OpenCV → for each frame: convert BGR to RGB → pass to MediaPipe → if hand detected, extract 63 landmarks → run model.predict() → if confidence > 0.8, display the letter → accumulate letters into words → if hand still for 1.5 seconds, commit the letter → on spacebar press, speak the word with pyttsx3.
Phase 4 — Streamlit UI
Wrap the webcam loop in Streamlit using st.camera_input() or streamlit-webrtc for live video. Left column: live webcam with landmark overlay. Right column: current letter, accumulated word, confidence bar, "Speak" button, "Clear" button.

3 interview answers to memorize
"Why landmarks instead of raw images?"
Raw pixel models fail when lighting changes, the background shifts, or skin tones vary. Landmark coordinates are normalized and position-independent — the model learns the shape of the gesture, not what it looks like under specific lighting. It's also much lighter to train.
"Why ISL specifically?"
Most open-source sign language tools are built for ASL, which doesn't serve India's 63 million hearing-impaired people. ISL has different signs, different grammar structure, and far less open tooling. Building for ISL fills a real gap instead of adding to an existing pile.
"What would you improve next?"
Currently the model handles only static gestures — signs that are a single hand position. Many ISL words involve movement over time. The next step would be using LSTM networks to capture sequences of landmark frames, enabling full word-level recognition instead of just the alphabet.
